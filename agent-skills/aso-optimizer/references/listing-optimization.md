# ASO 商店文案优化

将已批准的定位和关键词决策转化为真实、符合平台规则的元数据。

## 前置条件

必须具备：

- 可用的 `aso-app-context.md`
- 关键词策略或明确批准的关键词集合
- 目标平台、商店地区和语言
- 已验证与禁止使用的声明

缺少关键词证据时，只输出定位草稿，并把关键词选择标记为假设。

## 工作流程

1. 阅读 [platform-metadata.md](platform-metadata.md)。
2. 阅读 [claim-safety.md](claim-safety.md)。
3. 分开 Apple 和 Google 交付物。
4. 起草一套推荐方案，以及最多两套具有不同假设的备选方案。
5. 保持品牌一致，并遵守已验证产品事实。
6. 将每项重要声明映射到声明台账。
7. 验证最终字段：

```bash
python3 scripts/check_metadata.py metadata.json
```

8. 修复硬性长度错误，将政策与声明警告交由人工审核。
9. 仅在用户提供当前商店文案时输出修改前后对比。

## 规则

- 不得虚构奖项、评分、用户数、准确率、价格、用户证言、合作关系或“官方”身份。
- 不得将未验证的产品计划写成当前功能。
- 即使关键词有市场证据，也不得堆砌关键词或使用不自然文案。
- 不得承诺预期排名或转化提升。
- 没有本地市场证据时，不得把英文关键词结论直接套用到其他语言。
- 第三方品牌和 IP 在获得批准前均视为受限词。
